# 为 3D 游戏添加 GoldSrc 兔子跳：分步教程

[中文简介](../README.zh-CN.md) · [English](START-HERE.en.md) · [所有语言](../README.md)

## 1. 提供真实项目和访问权限

优先提供游戏源代码项目。如果只有已安装的游戏，请提供游戏目录、具体版本和可用的模组接口。只能聊天、不能读写文件的 AI 需要你粘贴控制器源码或手动执行命令。没有可用的移动控制器扩展点，就不能保证实现。

在中文简介中复制 AI 提示词，填写路径。选择 `goldsrc-stock`（保留 HL1 起跳限速）或 `classic-bhop`（关闭该限速），并说明是否需要按住跳跃键自动连跳和 UPS 速度显示。自动连跳是额外功能，不是原版 HL1 的默认输入行为。

## 2. 先确认游戏如何移动

要求 AI 给出引擎和版本、角色控制器文件/类、移动函数、向上轴、速度单位、碰撞系统、输入来源以及客户端/服务器权限模型。文件名只是线索，不能替代验证。不要凭空编造函数地址。

## 3. 修改现有控制器

在真正写入角色速度的位置集成算法。不要让两个移动控制器同时运行。examples 中的独立示例用于学习和测试，不能直接替换所有游戏的控制器。保留碰撞、重力、平台移动、蹲下空间检测和游戏原有的跳跃条件。

引擎详细文档目前主要是俄语。让 AI 阅读对应的 [Unity](UNITY.md)、[Unreal Engine / 虚幻引擎](UNREAL.md)、[Godot](GODOT.md) 或 [其他引擎](OTHER-ENGINES.md) 指南，并翻译成中文，保持代码标识符、公式和单位不变。成品游戏请先看 [编译后的游戏](COMPILED-GAMES.md)。

## 4. 换算速度单位

先测量普通跑步速度。如果游戏中的 7.5 世界单位/秒对应 300 GoldSrc UPS，则换算比例是 `300 / 7.5 = 40`。30 UPS 的空中投影上限应换算为 `30 / 40 = 0.75` 世界单位/秒，不能直接把 30 填进以米为单位的控制器。

示例中 Unity/Godot 使用 40 GoldSrc 单位/世界单位；Unreal 使用厘米，因此示例比例为 0.4。这是示例标定，不是引擎强制常量。

## 5. 实现一个物理步

读取并锁存输入 → 判断是否真正允许起跳 → 按需执行一次原版起跳限速 → 地面摩擦或空中状态 → 水平加速 → 垂直物理 → 引擎碰撞移动 → 测量结果。

GoldSrc 空中加速用 `min(wishspeed, 30)` 限制目标方向上的速度投影，但加速度增量使用完整的 `wishspeed`。不要把总空中速度限制在 30 UPS。只有真正接受的起跳才能跳过地面摩擦；被低天花板阻挡的跳跃不应无限跳过摩擦。参见 [算法](ALGORITHM.md) 和 [Python 参考实现](../reference/goldsrc.py)。

注意 grounded 状态可能来自上一次物理移动。自动连跳应在落地后第一个允许的物理步触发，不能强行一直设置 grounded=true。保留正常跳跃高度。

## 6. 测试数学和游戏行为

先运行 `python tools/check.py`，再按照 [测试指南](TESTING.md) 测试对应语言和引擎。检查无输入空中惯性、A/D 转向加速、松开跳跃后的停止、连续跳跃、墙壁、低天花板、蹲下和重生。

联网游戏必须让服务器权威模拟与客户端预测使用一致规则，并用真实服务器和客户端测试。仅修改客户端不代表远程服务器支持新移动方式。

[VALIDATION.md](../VALIDATION.md) 记录实际测试情况。数学测试通过不代表 Unity/Unreal 编辑器或网络对局测试通过。本项目也不是 HL1 碰撞、水中移动和 surf 行为的完整移植。

# Контракт движения и формулы

Источник формул — [официальный HL1 SDK Valve](https://github.com/ValveSoftware/halflife/blob/master/pm_shared/pm_shared.c). Здесь собственная компактная реализация математики; исходный код SDK не включён и его лицензия не заменяется MIT этого проекта.

## Данные одного шага

`v` — текущая горизонтальная скорость; `wish` — желаемый вектор; `dt` — секунды; `maxspeed` — разрешённая длина желаемой скорости. Направление `d=wish/length(wish)` вычисляют из ненулевого исходного вектора, `w=min(length(wish),maxspeed)`.

Входные `grounded` и `jump_accepted` — разные факты. `jump_accepted` означает, что персонаж действительно может прыгнуть: есть пол, управление разрешено, нет блокирующего состояния/потолка по правилам игры. Удержание кнопки — лишь намерение.

## Порядок

1. Получи вектор ввода, сохрани аналоговую длину, ограничь диагональ единицей.
2. Определи jump_accepted и режим `air = !grounded || jump_accepted`.
3. Если выбран stock-профиль, применяй его срез только при принятом прыжке.
4. Если !air, примени трение.
5. Добавь горизонтальное ускорение по формуле ниже.
6. В наземном режиме обнули остаток меньше 1 GS unit/s.
7. Передай скорость вертикальной физике и коллизиям движка ровно один раз.
8. После столкновения обнови фактическую скорость/нормали по контракту контроллера.

## Трение

Для скорости не ниже 0.1:

```
speed = length(v)
drop = max(speed, stopspeed) * friction * surface_friction * edge_multiplier * dt
v *= max(speed-drop, 0) / speed
```

Обычные значения: friction=4, stopspeed=100, surface_friction=1, edge_multiplier=1. Оригинальный edgefriction требует отдельной трассировки у обрыва. Если её нет, порт покрывает обычную поверхность, а не все детали PM_Friction.

## Ускорение

```
L = w                       # земля
L = min(w, air_wish_cap)    # воздух, cap=30
add = L - dot(v,d)
if add > 0:
    amount = min(add, accel * w * dt * surface_friction)
    v += amount * d
```

Обычные accel=10 и airaccel=10. В воздушном множителе используется w, а не L. Из покоя, w=300 и dt=0.001, добавится 3 units/s; при dt=0.016 — 30. Общая скорость в воздухе может быть выше maxspeed: ограничена проекция на d.

config/presets.json описывает выбранные профили, но не загружается контроллерами автоматически. Привяжи значения к конфигурации целевой игры; если изменяешь коэффициенты, добавь соответствующие параметры адаптера и проверки. Включённые C#/GDScript-ядра используют стандартные коэффициенты 10/4/100/30 и переключаемый limiter.

Если прыгнуть из покоя и держать строго вперёд без поворота, проекция быстро достигнет 30 и дальнейшего прямого воздушного разгона не будет. Для обычного старта сначала разбегаются по земле, затем прыгают; для набора скорости в воздухе меняют wish-направление стрейфом и поворотом. Принудительный разгон до run speed каждый прыжок изменил бы эту механику.

## Stock bunny limiter

При принятом новом прыжке и speed>1.7*maxspeed:

```
v *= (1.7*maxspeed/speed)*0.65
```

Получается 1.105*maxspeed. Оригинальный HL1 проверяет полную 3D-скорость до нового импульса; планарные ядра здесь совпадают с ним при нулевой вертикальной скорости на полу. Полный 3D-вариант нужен играм, где в этот момент остаётся существенная вертикальная/платформенная скорость.

## Единицы

Если scale — GS units в одной мировой единице: `v_gs=v_world*scale`; обратно делим на scale. Точно так же преобразуются wish, maxspeed, stopspeed, воздушный предел и малые пороги. Безразмерные 10, 4, 1.7, 0.65 не масштабируются.

Примеры выбирают scale=40 для Unity/Godot и 0.4 для Unreal в сантиметрах. Бег 7.5 м/с или 750 см/с тогда означает 300 UPS. Это калибровка демо, а не универсальная константа. В существующей игре измерь обычный бег и выбери масштаб явно.

## Что не является точным переносом всего HL1

Планарная формула не переносит BSP-коллизии, step-slide, surf, воду, лестницы, ground snapping, тайминги команд, анимации и сеть. Автопрыжок добавлен отдельно. Нельзя называть весь movement «1:1» только потому, что выполнено PM_AirAccelerate.
